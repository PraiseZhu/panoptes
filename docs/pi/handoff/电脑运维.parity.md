## 一、门控：谁读什么
| 侧 | 读什么 | 什么时候干活 |
|---|---|---|
| Grok box-health | `/workspace/fleet-mode` | 值是 `grok`，或者文件不存在 → 跑全套；值是 `pi` → 立刻退出（不调模型、不发消息） |
| Pi boxhealth.py（**已修**） | `fleet-mode`（lib.mode()）**加** `takeover/boxhealth` | 两个条件都满足才跑：`fleet-mode=pi` 且 marker 存在 |
| switch.sh | 写 fleet-mode，同时建或删 takeover/{cindy,boxhealth} | 正常切换时两者一致 |

**不一致的情况**：有人只改了 fleet-mode，或者只建/删了 marker。
- 修之前：Pi 线只看 marker。`fleet-mode=grok` 但 marker 还在时，**两线会同时跑**，Grok 那边真删、Pi 这边列清单，告警重复；`fleet-mode=pi` 但没有 marker 时，**两线都不跑**。
- 修之后：`fleet-mode≠pi` 时 Pi 一定不跑，所以不会双跑。`fleet-mode=pi` 但没有 marker 时，Pi 也不跑，只在日志里写 `WARN gate mismatch …（两线都不跑！请 switch.sh pi）`。这种情况仍然没有人做体检，见第五节决定 4。
- 证据（dry-run，用 PI_FLEET_MODE / PI_TAKEOVER_DIR 模拟）：mode=pi 加 marker → 正常输出一行体检；mode=grok 加 marker → `WARN … Grok 线在管，marker 多余`，跳过；mode=pi 不加 marker → `WARN … 两线都不跑`，跳过。
- 一键切换：`switch.sh pi|grok` 一次就够。Grok routine 恢复启用以后，切线只需要改 fleet-mode 这一个文件。如果手动只改了 fleet-mode，Pi 线**宁可停也不双跑**。

## 四、F4：内存<3G 时 Pi 跳过 Cindy 保活
- 位置：`/workspace/pi-fallback/bin/run.sh` 里的 `if [ "$avail" -lt 3072 ]; then echo "skip…"; exit 0; fi`。它对**所有作业**生效，cindy.py 本身没有内存判断。Grok 的「Cindy 保活」routine 没有这条门控。
- 权衡：
  - 不豁免：内存低时 Cindy 挂了就一直不拉起，可能离线好几个小时。而内存低往往就是 Cindy 被杀的原因，恢复最需要它的时候它恰好不跑。
  - 豁免：重启 Electron 大约要 1.5G。可用 <3G 时拉起，可能把内存压到 earlyoom 的 10% 线以下（15G 的 10% 约 1.5G），earlyoom 就会去杀别的进程（Cindy 在 avoid 名单里），可能杀到 panoptes、nightly、claude 这些。
- **建议**：豁免，但不是无条件豁免。分两种情况：
  1. Cindy 进程**在**：ensure 只做 nudge 和检查，基本不吃内存，任何时候都应该跑。
  2. Cindy **不在**、需要拉起：MemAvailable ≥ 2G（拉起 1.5G 之后还留约 0.5G，高于 earlyoom 线）才拉起，否则只记录和告警，下一个 5 分钟再试。
  - 实现方式：run.sh 的门控对 `cindy`（和 `boxhealth`）不生效，由 cindy.py / ensure-cindy.sh 自己判断“拉起前要 ≥2G”。这要改 Cindy 管家和 run.sh 维护者的文件，**我没改，只是建议**。
  - 同样，boxhealth 也应该豁免 run.sh 门控，否则 <3G 告警永远发不出去。boxhealth 本身很轻（不调模型，只用约几十 MB）。

### 剩余边界：需要 Cindy 管家在 ensure-cindy.sh / cindy.py 里改（我没改）
run.sh 只能判断“进程在不在”。Cindy **在**的时候，ensure-cindy.sh 里还有几条会重启 Cindy 的路径：relaunch-with-script（不是用启动脚本起的）、relaunch-no-window（≤1 次/小时）、install-downloaded（新 .deb 装完会重启）。这几条在 <2G 时仍然可能触发。建议 Cindy 管家这样改：
1. 在 ensure-cindy.sh 里所有 kill+relaunch / start 分支前加一句：`[ "${PI_MEM_AVAIL_MB:-99999}" -lt 2048 ] && { echo "STATUS=lowmem-defer"; exit 0; }`（run.sh 已经导出这个变量），或者自己读 /proc/meminfo，这样 Grok 线也能用。
2. 只读的 nudge 和检查不受影响。
3. cindy.py 不用改：遇到 PI_LOWMEM=1 时已经走 dry-run。可以选做：把 `PI_LOWMEM` 写进报告标题。
